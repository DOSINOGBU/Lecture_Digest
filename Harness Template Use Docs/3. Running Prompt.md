# Running Prompt

아래 프롬프트는 프로젝트용 하네스 초기화가 끝난 뒤, 실제 구현을 시작할 때 사용합니다.

한 번에 전체 앱을 만들게 하지 않고, `docs/exec-plans/active/`에 있는 작업 중 하나만 구현하게 하는 것이 핵심입니다.

```text
 `docs/exec-plans/active/`에 있는 `.md` 계획 파일을 파일명 오름차순으로 정렬하고,
가장 낮은 번호의 아직 완료되지 않은 계획 하나만 실행해줘.

중요:
- "우선순위"는 파일명 숫자 접두사(00, 01, 02...)만 의미해.
- 00번처럼 코드 구현이 아닌 검증/조사/문서 산출물 작업이어도 건너뛰지 마.
- 선택한 계획 파일명을 먼저 보고한 뒤, 그 파일의 Goal/Scope/Steps/Validation 범위 안에서만 작업해줘.
- 가장 낮은 번호의 계획이 사용자 결정이나 외부 자료 때문에 막히면 다음 번호로 넘어가지 말고 차단 사유와 필요한 결정을 보고해줘.

규칙:
- 작업 전 AGENTS.md와 관련 문서를 읽어줘.
- 한 번에 하나의 계획만 실행해줘.
- 큰 파일이 생기지 않게 책임을 분리해줘.
- 로딩/빈/오류 상태가 관련된 작업이면 반드시 포함해줘.
- 구현 또는 검증 후 관련 테스트/검증을 실행하고 결과를 보고해줘.
- 검증 후 `scripts/recommend-version-control.ps1 -VerificationStatus <Passed|Partial|Failed|NotRun>`를 실행하고 Commit/Push/PR 판단을 보고해줘.
- 커밋은 아직 하지 말고 변경 요약과 검증 결과만 알려줘.
```

## 반복 사용 방식

1. AI가 파일명 숫자 접두사 순서로 실행할 계획 하나를 고르고 선택한 파일명을 보고합니다.
2. 사람이 작업 범위가 적절한지 확인합니다.
3. AI가 구현하고 검증합니다.
4. 사람이 동작, UX, 범위 초과 여부를 확인합니다.

문제가 없으면 커밋/PR 단계로 넘어갑니다.

## 추가로 붙이면 좋은 조건

필요한 경우 아래 조건을 프롬프트 끝에 추가합니다.

```text
추가 조건:
- 새 파일이 필요하면 책임 단위별로 분리해줘.
- 500줄 이상 파일에 새 기능을 추가해야 한다면 먼저 분리 계획을 보고해줘.
- 외부 API 호출에는 실패 로그와 사용자에게 보여줄 오류 상태를 포함해줘.
- 테스트가 불가능한 부분은 수동 검증 방법을 명확히 적어줘.
```
