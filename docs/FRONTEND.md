# Frontend Guide

LectureDigest의 UI는 사용자가 실제 강의 처리와 학습을 시작하는 작업 화면이어야 합니다. MVP는 Streamlit 기반 데스크톱 웹/로컬 UI를 추천하고, 모바일은 읽기와 검색, 간단한 검수 정도의 반응형 지원을 목표로 합니다.

## UI Principles

- 첫 화면은 강의 라이브러리 또는 강의 등록처럼 실제 작업을 시작할 수 있어야 합니다.
- 긴 작업은 현재 단계, 예상 남은 시간, 실패 단계, 재시도 버튼을 보여줍니다.
- RAG 답변과 노트 문단은 출처 타임스탬프와 원본 점프 링크를 함께 표시합니다.
- 교정 후보는 원문, 수정안, confidence, reasoning, 승인/기각 액션을 나란히 보여줍니다.
- 검증 실패는 실패 항목과 자동 수정 여부를 분리해 보여줍니다.
- 모델 또는 prompt 변경으로 산출물이 stale 상태가 되면 자동 재생성하지 않고 수동 재생성 버튼을 제공합니다.
- OCR 입력이 없으면 화면 메모 섹션을 만들지 않고 옵션 비활성 상태를 표시합니다.
- 원문 OCR은 보관하되, 노트/RAG 화면에는 정제 OCR 반영 결과를 기준으로 보여줍니다.
- 복잡한 계산과 데이터 변환은 렌더링 코드 밖으로 분리합니다.

## Required Screens

| 화면 | 핵심 책임 |
|---|---|
| 강의 라이브러리 | 강의 목록, 카테고리, 빈 상태, 샘플 등록 CTA |
| 강의 등록/업로드 | 영상/자막/메타데이터 입력, 파일 검증 오류 표시 |
| 처리 진행 상태 | STT, OCR, 임베딩, 요약, 노트 생성 단계별 상태와 재시도 |
| 강의 상세 | 개요, 챕터, 섹션 요약, 원본 점프 링크 |
| 검색/RAG 챗 | 인용, 필터, 관련 구간, 근거 부족 상태 |
| 학습 노트 생성 요청 | 입력 챕터, 톤, OCR 사용 여부, 용어집 선택 |
| Markdown 노트 미리보기 | 타임스탬프, 콜아웃, 용어집, 셀프 체크 표시 |
| 교정 검수 | 원문/수정안/confidence/reasoning, 승인/기각 |
| 검증 결과 패널 | 헤더 중복, 스타일 위반, 용어집 보류, STT 의심 마커 |
| Anki 생성 | 카드 생성 상태, 미리보기, `.apkg` 또는 AnkiConnect 내보내기 |
| 퀴즈 생성 | Anki 이후 후속 기능으로 생성 상태와 출처 표시 |
| 설정 | API 키, 모델, 비용 제한, 로컬/클라우드 처리 범위 |

## State Requirements

| 상태 | 표시 기준 |
|---|---|
| Empty library | 지원 파일 형식과 강의 등록 CTA 표시 |
| Missing subtitle | STT 자동 전환과 예상 처리 시간 표시 |
| Missing transcript segments | "대본 입력이 필요합니다" 상태 표시 |
| Empty search result | 필터 초기화와 유사 키워드 제안 |
| Low evidence answer | 근거 부족과 검색 범위 확장 안내 |
| No correction candidates | "검수할 교정 후보 없음" 표시 |
| Validation failed | 실패 항목, 자동 수정 가능 여부, 재시도 액션 표시 |
| LLM quota/cost limit | 비용 제한 조정 또는 나중에 재시도 안내 |

## Component Rules

| 요소 | 원칙 |
|---|---|
| Container | 데이터 로딩, 상태 전환, 이벤트 연결 |
| Presentational | 표시와 사용자 입력만 담당 |
| Form | 입력 검증과 오류 메시지를 명확히 표시 |
| Progress view | 단계, 상태, 재시도 가능 여부, 마지막 오류 표시 |
| Citation view | 강의명, 챕터, 타임스탬프, 점프 액션 표시 |
| Review panel | 원문/수정안/근거를 보존하고 승인 전 자동 적용하지 않음 |

## Accessibility

- 키보드만으로 검색, 챕터 이동, 답변 출처 열기, 교정 승인/기각, 재시도 실행이 가능해야 합니다.
- 타임스탬프, 인용, 의심 마커는 색상 외 텍스트 레이블로도 구분합니다.
- Markdown 미리보기와 원본 대본 비교는 스크린 리더가 읽을 수 있는 구조를 유지합니다.
- 대용량 업로드와 장시간 처리 상태는 화면 리더가 상태 변화를 알 수 있게 설계합니다.
