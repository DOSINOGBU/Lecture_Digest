# Reliability

LectureDigest는 긴 작업과 외부 모델 호출을 포함하므로 실패를 예측 가능하게 만들고, 실패했을 때 부분 결과를 보존한 채 재개할 수 있어야 합니다.

## Failure Handling

- 예상 가능한 실패는 사용자에게 이해 가능한 메시지로 반환합니다.
- 예상하지 못한 실패는 원본 에러와 맥락을 함께 기록합니다.
- 외부 API, 네트워크, 파일 시스템 작업은 실패 가능성을 전제로 처리합니다.
- 실패를 잡았다면 처리하거나, 더 많은 맥락을 붙여 다시 던집니다.
- 입력 검증 실패와 시스템 실패를 같은 방식으로 다루지 않습니다.
- 실패한 단계 이후의 파생 산출물은 stale 상태로 표시하거나 재생성 후보로 남깁니다.

## Stage Recovery Rules

| 단계 | 실패 시 처리 |
|---|---|
| 강의 등록 | 파일/메타데이터 오류를 사용자 수정 가능 오류로 반환 |
| 자막 파싱 | 파싱 오류를 표시하고 STT fallback 가능 여부를 제안 |
| STT | 원본 파일/오디오 트랙 오류를 구분하고 재시도 가능 여부 기록 |
| OCR | OCR 없이 진행 가능한 경우 옵션 비활성 상태로 계속 진행 |
| 청킹/임베딩 | 실패한 청크 또는 벡터 저장 지점부터 재시도 |
| 요약/RAG | 모델/프롬프트/토큰 오류를 기록하고 캐시된 이전 결과 사용 여부 표시 |
| ScriptDigest | 입력 세그먼트가 없으면 생성 중단, 검증 실패는 `flagged` 저장 |
| 교정 | 낮은 confidence는 원문 유지와 검수 대기로 처리 |
| 카드/퀴즈 | 출처 매핑 실패 시 산출물을 확정하지 않음 |

## Validation

- 중요한 입력은 경계에서 빠르게 검증합니다.
- 검증 실패 메시지는 사용자가 고칠 수 있는 값을 알려줍니다.
- 내부 로직은 검증된 입력을 받는다는 전제를 코드 구조로 드러냅니다.
- ScriptDigest 출력은 헤더 중복, 헤더-내용 불일치, 길이, 톤, 표제어/조사, 용어집 fallback, 교정 적용, 학습 목표 단일 소스, STT 마커 수를 검사합니다.

## Retry Rules

| 상황 | 재시도 여부 | 조건 |
|---|---|---|
| 일시적 네트워크 실패 | 가능 | 제한된 횟수와 지수 백오프 |
| LLM/OCR/STT API rate limit | 가능 | 비용/쿼터 한도와 backoff 적용 |
| 입력 검증 실패 | 불가 | 사용자가 입력을 수정해야 함 |
| 권한 실패 | 불가 | 인증/권한 상태 확인 필요 |
| 멱등하지 않은 외부 호출 | 주의 | 중복 발생 영향 확인 후 결정 |
| 낮은 검색 근거 | 불가 | 검색 범위/질문/필터 조정 필요 |

## Timeouts

- 외부 호출에는 명시적 타임아웃을 둡니다. 기본값을 그대로 두지 않습니다.
- RAG 일반 질의는 30초 이내 답변을 목표로 합니다.
- 30분 챕터의 전체 학습 노트 생성은 5분 이내를 목표로 합니다.
- 강의 상세 화면의 저장된 요약/챕터/노트 조회는 2초 이내 표시를 목표로 합니다.
- 교정 후보 목록과 검증 결과는 3초 이내 열람을 목표로 합니다.

## Idempotency And Cache

- 같은 작업을 두 번 실행해도 결과가 같도록 설계합니다.
- 각 단계 결과는 입력 해시, 모델 버전, 프롬프트 버전 기준으로 캐시합니다.
- 외부 호출 측에 멱등 키 또는 중복 검출 수단을 둡니다.
- 자동 교정은 원문과 수정안을 모두 저장해 되돌릴 수 있어야 합니다.
- validation 실패는 자동 수정 가능한 항목을 1차 수정한 뒤 재검증합니다.
- 프롬프트/모델 버전 변경 시 캐시를 무효화하거나 stale 상태로 표시하되 자동 재생성하지 않습니다.
- stale 산출물은 사용자가 수동 재생성 버튼 또는 명시적 명령을 실행할 때만 다시 생성합니다.

## Recovery Notes

장애 대응에 필요한 명령, 대시보드, 로그 위치는 구현 스택 확정 후 `docs/RUNBOOK.md`와 `.harness/checklists/incident.md`에 구체화합니다.
