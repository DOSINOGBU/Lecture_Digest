# Plan: File And Folder Ingestion Routing

## Goal

파일 단위와 폴더 단위 강의 입력을 모두 지원할 수 있도록 입력 규칙, 자막 매칭, STT 분기, 클립 메타데이터 계획을 확정합니다.

## Scope

- 기존 파일 단위 입력은 `video`와 선택 `subtitle`을 분리해서 유지합니다.
- 영상만 입력하면 STT 대상, 영상과 자막을 함께 입력하면 자막 대체 대상으로 분기합니다.
- 폴더 단위 입력은 `강의명 / 대분류 / 중분류 / 영상 클립` 구조를 기본으로 자동 추론합니다.
- 중분류 하위에 `자막`, `자막파일`, `subtitles`, `captions` 폴더가 있으면 STT를 생략하고 자막 파일을 사용합니다.
- 자막 매칭은 파일명 stem 우선, 실패 시 번호 접두사 보조 매칭을 사용합니다.
- 자막 폴더가 없으면 해당 중분류의 모든 영상 클립을 STT 대상으로 표시합니다.
- 자막 폴더가 있는데 일부 클립이 매칭되지 않으면 자동 STT로 넘기지 않고 `subtitle_unmatched`로 표시합니다.
- 내부 처리 단위는 영상 클립 1개이며 `lecture_title`, `major_category`, `middle_category`, `clip_title`을 보존합니다.

## Out Of Scope

- 실제 OpenAI STT API 호출 구현.
- OCR, 교정, 임베딩, 노트 생성.
- Streamlit 업로드 UI.

## Assumptions

- 지원 영상 확장자는 현재 입력 파이프라인의 `.mp4`, `.mkv`, `.mov`, `.webm`를 유지합니다.
- 지원 자막 확장자는 `.srt`, `.vtt`를 유지합니다.
- 폴더 입력에서 빈 폴더와 지원하지 않는 파일은 명시적인 issue로 기록합니다.
- 파일 단위 입력에서 제목/강사/카테고리 필드는 기존 필수 메타데이터 정책을 유지합니다.

## Steps

- [x] 폴더 입력 구조와 클립 메타데이터 매핑 규칙을 문서화한다.
- [x] 자막 폴더 탐지 이름과 자막 매칭 우선순위를 정의한다.
- [x] 파일 단위 입력의 영상만/영상+자막 분기 상태를 정의한다.
- [x] 폴더 단위 입력의 STT 대상, 자막 대체 대상, 매칭 실패 상태를 정의한다.
- [x] CLI 또는 use case 명령 형태와 출력 요약 형식을 정한다.
- [x] 빈/진행/오류 상태와 issue code를 정리한다.

## Validation

- 영상만 입력하면 STT 대상 상태로 등록됩니다.
- 영상과 자막을 함께 입력하면 STT를 건너뛰고 자막 세그먼트를 사용합니다.
- 정상 폴더 구조에서 여러 클립이 개별 처리 단위로 등록됩니다.
- 자막 폴더가 있으면 stem 기준 매칭이 우선 적용됩니다.
- 자막 폴더가 없으면 해당 중분류의 모든 클립이 STT 대상으로 표시됩니다.
- 일부 자막 매칭 실패는 `subtitle_unmatched`로 남고 자동 STT로 전환되지 않습니다.

## Risks

- 실제 강의 폴더명이 예상보다 불규칙하면 자동 추론 실패가 늘어날 수 있습니다.
- 자막 파일명과 영상 파일명이 다르면 stem 매칭만으로 부족할 수 있습니다.
- 폴더 단위 등록이 너무 많은 클립을 한 번에 만들면 이후 API 비용 추정이 어려워질 수 있습니다.

## Result

`register-folder` CLI와 `register_lecture_folder` use case를 추가했습니다. 폴더 구조는 `강의명 / 대분류 / 중분류 / 영상 클립`으로 추론하고, 자막 폴더 이름은 `자막`, `자막파일`, `subtitles`, `captions`를 지원합니다. 자막 매칭은 stem 우선, 번호 접두사 보조 순서로 처리하며, 자막 폴더가 있는데 매칭되지 않은 클립은 `subtitle_unmatched`로 남기고 STT로 자동 전환하지 않습니다. 빈 폴더는 empty 상태로 출력하고, 누락 폴더는 `folder_not_found` 오류로 반환합니다.
