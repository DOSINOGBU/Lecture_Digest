# Plan: Phase 0 Baseline Validation

## Goal

보유 강의 1개와 1챕터를 기준으로 NotebookLM, 단일 LLM 호출, 수동 골든 노트를 비교해 LectureDigest가 직접 구현해야 할 차별 영역을 확인합니다.

## Scope

- 샘플 강의와 챕터 1개 선정.
- 원본 대본 또는 자막 확보.
- 수동 골든 노트 작성 기준 정의.
- 비교 항목: 요약 품질, 출처 정확도, 누락 개념, 비용/시간, 노트 가독성.

## Out Of Scope

- 자동 파이프라인 구현.
- UI 구현.
- 대량 강의 처리.

| 로컬 원본 | 사용자 제공 로컬 파일을 사용하며, 저장소 문서에는 전체 로컬 경로를 기록하지 않음 |

## Baseline Input Check

| 입력 | 확인 결과 |
|---|---|
| 영상 | MP4 존재 확인, 1920x1080, H.264, 약 25분 37초 |
| 자막 | SRT 존재 확인, 564개 세그먼트, 약 12,312자, 마지막 타임스탬프 `00:25:35.080` |
| 키워드 신호 | HTML, CSS, DOM, V8, caniuse.com, IE, iOS 등 |
| OCR 필요 여부 | 필요 가능성이 높음. 대표 프레임에서 web.dev 문서, 렌더링 흐름 도식, caniuse 호환성 표가 확인됨 |

OCR은 MVP 정책에 맞춰 원문 OCR을 보관하되, 노트/RAG에는 정제된 OCR만 반영하는 방향을 유지합니다. 이 Phase 0에서는 실제 OCR을 실행하지 않고, 화면 텍스트 의존도가 있는 샘플이라는 사실만 기록합니다.

## Golden Note Minimum Structure

수동 골든 노트는 비교 기준이므로 아래 구조를 최소 요구사항으로 둡니다.

1. 메타데이터: 강의명, 챕터명, 원본 범위, 작성자, 작성일.
2. TL;DR: 강의 핵심을 3~5문장으로 요약.
3. 학습 목표: 학습자가 이해해야 할 개념 3~7개.
4. 개념 노트: DOM, 렌더링 엔진, HTML/CSS 파싱, 브라우저 호환성처럼 개념별로 정리.
5. 출처 매핑: 주요 주장마다 SRT segment 또는 타임스탬프를 연결.
6. 화면 근거: 화면 자료가 없으면 이해가 떨어지는 도식/표/사이트를 별도 표시.
7. 용어집: 전문 용어, 영문 약어, 오인식 가능 용어.
8. 복습 후보: Anki 카드로 전환할 질문/답변 후보.
9. 검증 메모: 원본에 없는 추론, 누락 가능성, OCR 필요 항목.

## Baseline API Setup

단일 LLM baseline은 OpenAI Responses API와 `gpt-4o`를 기준으로 둡니다. `OPENAI_API_KEY`는 사용자 환경변수에서 읽고, 키 값 자체는 출력하거나 문서에 기록하지 않습니다.

준비 절차:

1. OpenAI Platform dashboard에서 프로젝트용 API key를 생성합니다.
2. Windows PowerShell에서 사용자 환경변수로 저장합니다: `setx OPENAI_API_KEY "your_api_key_here"`.
3. 새 PowerShell 세션을 열고 `OPENAI_API_KEY`가 실제 OpenAI key로 설정되었는지 확인합니다. 값 자체는 출력하거나 문서에 기록하지 않습니다.
4. 여러 조직/프로젝트를 쓰는 경우에는 API 요청 헤더에 사용할 project id도 별도 환경변수로 둡니다.
5. baseline 실행 시 입력은 이 샘플의 SRT transcript와 타임스탬프를 사용하고, 원본 영상/전체 로컬 경로/API key는 외부로 보내거나 로그에 남기지 않습니다.

## Direct Implementation Decision

초기 NotebookLM 비교는 제외했지만, gpt-4o 단일 호출만으로는 PRD의 출처 정확도, 화면 근거 처리, 검증 가능한 학습 노트 요구를 충분히 만족하지 못했습니다. 따라서 직접 구현 범위는 축소하지 않고 유지합니다.

유지할 차별 영역:

- 원본 segment id와 타임스탬프를 보존하는 청킹/요약/RAG payload.
- 화면 자료를 위한 OCR 원문 보관과 정제 OCR의 노트/RAG 반영.
- 출처 누락, 추론 표기, 화면 근거 누락을 잡는 검증 게이트.
- 사람이 승인할 수 있는 AI 초안 골든 노트와 리뷰 메모.
- 답변까지 포함된 Anki 후보 생성과 품질 검수.

## Evaluation Criteria

| 항목 | 판정 기준 |
|---|---|
| 출처 정확도 | 모든 주요 주장에 타임스탬프 또는 segment id가 100% 연결되는가 |
| 누락 개념 | DOM, 렌더링 흐름, HTML/CSS 처리, 브라우저 호환성처럼 핵심 개념이 빠지지 않는가 |
| 환각 | 원본에 없는 정보를 원본처럼 말하지 않고, 필요한 부연은 `(추론)`으로 표시하는가 |
| 화면 의존 처리 | 도식/표/사이트 화면이 필요한 부분을 누락하지 않고 OCR 필요 항목으로 표시하는가 |
| OCR 해상도 | OCR이 영상 원본 해상도인 1920x1080 프레임에서 수행됐는가 |
| 노트 가독성 | 원문 반복을 줄이면서 학습 흐름이 유지되는가 |
| 복습 전환성 | 질문, 답변, 출처가 있어 Anki 카드로 바로 전환 가능한가 |
| 비용/시간 | 수동 작성 시간, 외부 도구 처리 시간, LLM 호출 비용을 기록할 수 있는가 |

## Validation

- `ffprobe`로 영상 메타데이터를 확인했습니다.
- 현재 SRT 파서로 자막 세그먼트 수, 타임스탬프, 문자 수를 확인했습니다.
- 대표 프레임 3개를 추출해 화면 자료 의존도를 수동 확인했습니다.
- 대표 프레임 3개가 모두 원본 해상도인 1920x1080임을 확인했습니다.
- 로컬 OCR 엔진(`tesseract`)은 현재 환경에서 찾지 못해 실제 OCR은 아직 수행하지 않았습니다.
- `OPENAI_API_KEY` 사용자 환경변수를 통해 gpt-4o baseline 호출이 성공했습니다.
- 비교표에는 출처 정확도, 누락 개념, 환각 여부, 화면 의존 처리, 노트 길이, 처리 시간을 기록합니다.
- 직접 개발해야 할 항목과 단일 LLM 호출로 충분하지 않은 항목을 분리했습니다.

## Risks

- NotebookLM은 초기 비교에서 제외했으므로 초기 차별성 판단은 gpt-4o baseline과 사람 승인 골든 노트에 의존합니다.
- 단일 LLM 비교는 API 키와 호출 로그가 없으면 재현 가능한 산출물로 남길 수 없습니다.
- 샘플 강의 1개가 전체 도메인을 대표하지 못할 수 있습니다.
- 화면 자료가 많은 강의는 자막만으로 노트를 만들면 핵심 도식이나 표가 누락될 수 있습니다.

## Open Questions

## Result

Phase 0에서 샘플 강의, 입력 품질, OCR 필요성, 골든 노트 최소 구조, 비교 기준, 저장소 보존 정책, 사람 승인 정책을 확정했습니다. NotebookLM은 초기 제외, 단일 LLM 기준 모델은 `gpt-4o`, 골든 노트는 AI 초안 후 사용자 본인 승인 방식으로 반영했습니다. gpt-4o baseline 생성과 예비 비교 결과, 단일 호출만으로는 출처/OCR/검증 요구를 충분히 만족하지 못하므로 직접 구현 범위는 유지하는 것으로 판단했습니다.
