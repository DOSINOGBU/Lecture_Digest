# Plan: Phase 0 Baseline Validation

## Goal

보유 강의 1개와 1챕터를 기준으로 NotebookLM, 단일 LLM 호출, 수동 골든 노트를 비교해 LectureDigest가 직접 구현해야 할 차별 영역을 확인합니다.

## Scope

- 샘플 강의와 챕터 1개 선정.
- 원본 대본 또는 자막 확보.
- 수동 골든 노트 작성 기준 정의.
- 비교 항목: 요약 품질, 출처 정확도, 누락 개념, 비용/시간, 노트 가독성.

## Out Of Scope

- 자동 파이프라인 구현.
- UI 구현.
- 대량 강의 처리.

## Selected Sample

| 항목 | 내용 |
|---|---|
| 샘플 | `02. 결국 브라우저가 이해하는 것` |
| 도메인 | 웹 브라우저, JS, HTML, CSS, DOM, 브라우저 호환성 |
| 선정 이유 | 화면 자료와 자막이 모두 있고, 코드/브라우저 개념과 시각 자료가 섞여 있어 PRD의 전문 강의 시나리오를 검증하기 좋음 |
| 로컬 원본 | 사용자 제공 로컬 파일을 사용하며, 저장소 문서에는 전체 로컬 경로를 기록하지 않음 |

## Baseline Input Check

| 입력 | 확인 결과 |
|---|---|
| 영상 | MP4 존재 확인, 1920x1080, H.264, 약 25분 37초 |
| 자막 | SRT 존재 확인, 564개 세그먼트, 약 12,312자, 마지막 타임스탬프 `00:25:35.080` |
| 키워드 신호 | HTML, CSS, DOM, V8, caniuse.com, IE, iOS 등 |
| OCR 필요 여부 | 필요 가능성이 높음. 대표 프레임에서 web.dev 문서, 렌더링 흐름 도식, caniuse 호환성 표가 확인됨 |

OCR은 MVP 정책에 맞춰 원문 OCR을 보관하되, 노트/RAG에는 정제된 OCR만 반영하는 방향을 유지합니다. 이 Phase 0에서는 실제 OCR을 실행하지 않고, 화면 텍스트 의존도가 있는 샘플이라는 사실만 기록합니다.

## Golden Note Minimum Structure

수동 골든 노트는 비교 기준이므로 아래 구조를 최소 요구사항으로 둡니다.

1. 메타데이터: 강의명, 챕터명, 원본 범위, 작성자, 작성일.
2. TL;DR: 강의 핵심을 3~5문장으로 요약.
3. 학습 목표: 학습자가 이해해야 할 개념 3~7개.
4. 개념 노트: DOM, 렌더링 엔진, HTML/CSS 파싱, 브라우저 호환성처럼 개념별로 정리.
5. 출처 매핑: 주요 주장마다 SRT segment 또는 타임스탬프를 연결.
6. 화면 근거: 화면 자료가 없으면 이해가 떨어지는 도식/표/사이트를 별도 표시.
7. 용어집: 전문 용어, 영문 약어, 오인식 가능 용어.
8. 복습 후보: Anki 카드로 전환할 질문/답변 후보.
9. 검증 메모: 원본에 없는 추론, 누락 가능성, OCR 필요 항목.

## Baseline Comparison Plan

| 기준선 | 현재 상태 | 필요한 다음 입력 |
|---|---|---|
| 수동 골든 노트 | 최소 구조와 평가 기준 정의 완료 | 사람이 실제 골든 노트를 작성하거나 승인 |
| NotebookLM | 저장소 안에서 자동 실행 불가 | 사용자가 동일 SRT/영상으로 NotebookLM 결과를 내보내기 |
| 단일 LLM 호출 | 저장소에 모델/provider/prompt가 아직 없음 | 사용할 모델, prompt, 호출 방식 결정 |
| LectureDigest 현재 구현 | 자막 파싱과 청킹까지 로컬 검증 가능 | 요약/RAG/노트 생성 단계 구현 후 비교 |

## Evaluation Criteria

| 항목 | 판정 기준 |
|---|---|
| 출처 정확도 | 주요 주장에 타임스탬프 또는 segment id가 연결되는가 |
| 누락 개념 | DOM, 렌더링 흐름, HTML/CSS 처리, 호환성 확인처럼 핵심 개념이 빠지지 않는가 |
| 환각 | 원본에 없는 정보를 원본처럼 말하지 않는가 |
| 화면 의존 처리 | 도식/표/사이트 화면이 필요한 부분을 누락하지 않는가 |
| 노트 가독성 | 원문 반복을 줄이면서 학습 흐름이 유지되는가 |
| 복습 전환성 | Anki 카드 후보로 바꾸기 쉬운가 |
| 비용/시간 | 수동 작성 시간, 외부 도구 처리 시간, LLM 호출 비용을 기록할 수 있는가 |

## Validation

- `ffprobe`로 영상 메타데이터를 확인했습니다.
- 현재 SRT 파서로 자막 세그먼트 수, 타임스탬프, 문자 수를 확인했습니다.
- 대표 프레임 3개를 추출해 화면 자료 의존도를 수동 확인했습니다.
- 비교표에는 출처 정확도, 누락 개념, 환각 여부, 화면 의존 처리, 노트 길이, 처리 시간을 기록합니다.
- 직접 개발해야 할 항목과 외부 도구로 충분한 항목은 NotebookLM/단일 LLM 결과 확보 후 분리합니다.

## Risks

- NotebookLM 결과는 외부 수동 실행이 필요해 저장소만으로 재현되지 않습니다.
- 단일 LLM 비교는 모델, prompt, 입력 범위가 정해지지 않으면 공정한 비교가 어렵습니다.
- 샘플 강의 1개가 전체 도메인을 대표하지 못할 수 있습니다.
- 화면 자료가 많은 강의는 자막만으로 노트를 만들면 핵심 도식이나 표가 누락될 수 있습니다.

## Open Questions

- 수동 골든 노트 작성자는 누구이며 어떤 품질 기준으로 승인할 것인가?
- NotebookLM 산출물은 어떤 형식(Markdown, PDF, 복사 텍스트)으로 저장할 것인가?
- 단일 LLM baseline에 사용할 모델, prompt, 입력 범위는 무엇인가?
- Phase 0 비교 산출물을 저장소에 보관할지, 로컬 비공개 자료로 둘지 결정해야 합니다.

## Result

Phase 0를 시작해 샘플 강의, 입력 품질, OCR 필요성, 골든 노트 최소 구조, 비교 기준을 확정했습니다. NotebookLM과 단일 LLM baseline은 외부 실행 결과가 필요하므로 아직 완료하지 않았습니다.
