# Observability

AI와 사람이 실패 원인을 빠르게 찾을 수 있도록 로그와 디버깅 신호를 정리합니다. LectureDigest는 장기 파이프라인과 외부 모델 호출이 많으므로 단계, 입력 해시, 모델/프롬프트 버전, 비용, 실패 원인을 추적해야 합니다.

## Log Format

```text
[ComponentName] action status { metadata }
```

예시:

```text
[LectureIngestion] register success { lectureId, hasSubtitle, category }
[TranscriptJob] stt failed { lectureId, stage, errorCode, retryable }
[ScriptDigest] validation flagged { lectureId, chapterId, failedRules }
```

## Log Policy

- 로그는 실패 위치나 중요한 결정을 좁히는 데 도움이 될 때 남깁니다.
- 의미 없는 로그(`here`, `test`)나 반복 루프의 과도한 로그는 남기지 않습니다.
- 식별자, 개수, 선택된 경로, 모델명, prompt 버전, 비용 추정처럼 원인 분석에 필요한 맥락을 포함합니다.
- 비밀값, 토큰, 전체 원본 대본, 결제/계정 정보, 불필요한 파일 경로는 직접 남기지 않습니다.

## Required Log Points

| 상황 | 로그 |
|---|---|
| 강의 등록 | lecture_id, 파일 유형, 자막 여부, 초기 상태 |
| STT 시작/완료/실패 | 모델명, 언어, 처리 시간, 세그먼트 수, 오류 코드 |
| OCR 시작/완료/실패 | 키프레임 수, 중복 제거 수, OCR 결과 수 |
| 청킹/임베딩 | 청크 설정, 청크 수, 임베딩 모델, 벡터 저장 결과 |
| 요약 생성 | L1/L2/L3 단계, 모델명, prompt 버전, 토큰 사용량 |
| RAG 질의 | 필터, 검색 방식, 근거 청크 수, reranker 사용 여부 |
| RAG 답변 | 답변 생성 여부, 인용 수, 근거 부족 여부 |
| 노트 생성 | 입력 챕터, 토큰 범위, tone, OCR 사용 여부 |
| STT 보정 | 의심 세그먼트 수, 자동 보정 수, 실패 마커 수 |
| 맥락 교정 | Pass A/B/C 후보 수, 자동 적용 수, 검수 대기 수 |
| Rewrite 검증 | 재시도 횟수, 스타일 위반 항목 |
| 용어집 | 등재/보류 수와 보류 사유 |
| 출력 검증 | 실패 규칙, 자동 수정 여부, 최종 status |
| 카드/퀴즈 생성 | 생성 수, 실패 수, 출처 매핑 여부 |
| 수동 재생성 | 사용자 액션, 대상 산출물, 이전/새 모델 버전, 비용 추정 |
| 외부 API 요청 | 시작, 성공, 실패, retryable 여부 |
| 재시도 | 시도 횟수와 실패 원인 |
| 예외 | 원본 에러와 작업 맥락 |

## Metrics

| 지표 | 목표 또는 용도 |
|---|---|
| 강의 처리 시간 / 영상 길이 | 0.3배 이하 목표 |
| RAG 응답 시간 | 일반 질의 30초 이내 |
| 출처가 있는 답변 비율 | 답변 신뢰도 확인 |
| 근거 부족으로 거부한 답변 수 | 환각 방지 품질 확인 |
| 자동 교정 precision 표본 | 95% 이상 목표 |
| 자동 교정 false positive 표본 | 1% 이하 목표 |
| 노트 길이 / 원본 길이 | 40~70% 목표 |
| LLM 토큰/비용 | 비용 한도와 캐시 효과 확인 |
| 단계별 실패율 | 병목과 신뢰성 개선 우선순위 |

## User-Facing Error Messages

- "STT 처리에 실패했습니다. 원본 파일을 읽을 수 없거나 오디오 트랙이 없습니다."
- "입력 대본 세그먼트가 없어 노트를 생성할 수 없습니다."
- "전사 의심 구간 일부를 자동 보정하지 못했습니다. 노트에 마커로 표시했습니다."
- "자동 교정 confidence가 낮아 사용자 검수가 필요합니다."
- "검색 근거가 충분하지 않아 답변을 생성하지 않았습니다. 검색 범위를 넓혀보세요."
- "출력 검증을 통과하지 못했습니다. 헤더 중복 또는 스타일 위반을 확인하세요."
- "LLM 호출 한도에 도달했습니다. 비용 제한을 높이거나 나중에 다시 시도하세요."

## Debugging Notes

자주 보는 로그 위치, 대시보드, 브라우저 확인 방법은 구현 스택 확정 후 기록합니다.
