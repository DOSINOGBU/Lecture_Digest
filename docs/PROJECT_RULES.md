# Project Rules

AI 에이전트와 사람이 함께 지켜야 하는 LectureDigest 프로젝트 규칙입니다. 부드러운 권장보다 실행 가능한 제약으로 작성합니다.

## Decision Priority

판단이 충돌하면 아래 순서로 결정합니다.

1. 디버깅 가능성
2. 원본 근거와 출처 보존
3. 읽기 쉬움
4. 안정성
5. 성능과 비용
6. 짧음

## Product Constraints

| 제약 | 이유 | 예외 처리 |
|---|---|---|
| 원본 segment id와 타임스탬프 매핑을 잃지 않습니다. | RAG 출처, 노트 검증, 원본 점프 링크의 기반 | 매핑이 불가능한 산출물은 `inferred` 또는 `unmapped` 상태로 표시 |
| 출처 없는 정보를 원본처럼 표시하지 않습니다. | 환각 방지와 학습 신뢰도 유지 | LLM 부연은 `(추론)`으로 명시 |
| 낮은 confidence 교정은 자동 적용하지 않습니다. | false positive가 학습 내용을 훼손할 수 있음 | 검수 대기 또는 원문 유지 후 correction log에 기록 |
| 강의 원본, 대본, 노트를 자동 공유하지 않습니다. | 저작권과 개인 자료 보호 | 사용자가 명시적으로 내보내기 요청한 범위만 허용 |
| 장기 작업은 단계별 상태와 재시도 지점을 남깁니다. | STT/OCR/LLM 실패 후 복구 필요 | 단기 프로토타입도 최소한 실패 단계와 원본 예외를 기록 |
| 모델명, prompt 버전, 입력 해시를 추적합니다. | 캐시 재사용과 재현성 판단에 필요 | 외부 도구가 제공하지 않으면 실행 메타데이터에 `unknown` 기록 |
| 새 의존성은 승인 없이 추가하지 않습니다. | 보안, 비용, 유지보수 영향 | 필요성, 대안, 영향 범위를 먼저 설명 |
| 자동 생성 파일은 직접 수정하지 않습니다. | 재생성 시 변경이 사라짐 | 생성 원본 또는 스키마를 수정 |
| 관련 없는 리팩터링을 섞지 않습니다. | 리뷰와 롤백이 어려움 | 별도 작업 계획으로 분리 |
| 검증 없이 완료를 선언하지 않습니다. | 실제 동작을 확인하지 못하면 회귀를 숨길 수 있음 | 실행 불가 사유와 대체 확인 방법을 기록 |
| 비밀값을 커밋하지 않습니다. | 보안 사고 방지 | `.env.example`에는 키 이름과 설명만 기록 |

## Functional Guardrails

- 강의 등록은 지원 파일 형식, 파일 존재 여부, 필수 메타데이터를 경계에서 검증합니다.
- 자막이 있으면 STT를 건너뛰되, 자막 파싱 실패는 명확히 드러냅니다.
- ScriptDigest는 대본 세그먼트 배열과 강의 메타데이터가 없으면 노트를 생성하지 않습니다.
- 노트 생성 권장 단위는 챕터 단위이며, 5~30분 또는 약 3,000~15,000 토큰을 넘으면 분할 경고를 냅니다.
- 학습 노트 출력은 헤더 중복, 스타일 위반, 용어집 fallback, STT 마커 수 등 검증 게이트를 통과해야 합니다.
- RAG 답변은 검색 근거가 부족하면 답변 생성을 거부하거나 근거 부족을 명시합니다.

## Event To Action

| 이벤트 | 필수 행동 |
|---|---|
| 기능 추가 | PRD 관련 FR 확인, 상태/빈/오류 흐름 기록, 테스트 또는 수동 시나리오 작성 |
| 파이프라인 단계 추가 | 입력/출력 스키마, 캐시 키, 실패 상태, 재시도 가능 여부 기록 |
| LLM/OCR/STT 호출 추가 | 모델명, prompt 버전, 비용 추정, 민감정보 전송 범위 기록 |
| 데이터 모델 변경 | 삭제/보존 정책, 마이그레이션/롤백 전략 기록 |
| 버그 수정 | 재현 조건, 가능한 원인 3~5개, 확인된 원인, 최소 수정, 재검증 기록 |
| 설정 변경 | 영향 범위, 기본값, 롤백 방법 기록 |
| 의존성 추가 | 이유, 대안, 라이선스/보안/비용 영향 기록 |

## Done Criteria

- 요구사항과 연결된 PRD 항목 또는 exec-plan 범위를 충족합니다.
- 관련 테스트 또는 수동 검증을 완료합니다.
- 실패 가능성과 남은 리스크를 기록합니다.
- 새로 알게 된 규칙, 용어, 운영 절차를 해당 문서에 반영합니다.
- 구현이 불가능하거나 위험한 미결정은 `docs/exec-plans/active/` 또는 관련 문서의 Open Questions에 남깁니다.
