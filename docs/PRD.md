# PRD

## 1. Product Summary
- 제품 이름: LectureDigest (강의 학습 가속화 시스템, ScriptDigest 통합본, v0.5 Draft, 통합일 2026-04-29)
- 한 줄 설명: 온라인 강의를 텍스트화하고, 검색 가능한 지식베이스, 계층 요약, 출처 기반 질의응답, 정제된 학습 노트, Anki 카드, 퀴즈로 변환하는 개인 학습 가속화 시스템.
- 해결하려는 문제: 사용자가 보유한 강의가 많고 길어 전체 시청이 비현실적이며, 단순 요약만으로는 핵심 지식이 장기 기억에 정착되지 않는다. 또한 강의대본은 구어체, 반복, filler word, STT 오류가 그대로 남아 있어 사람이 그대로 읽기 어렵다.
- 핵심 사용자: 코딩, 마케팅, 디자인, 자기계발 등 여러 분야의 온라인 강의를 많이 보유했지만 끝까지 시청하거나 체계적으로 복습하지 못하는 1인 학습자.

## 2. Goals
- 성공 기준: 사용자는 강의를 처음부터 끝까지 보지 않아도 전체 구조를 파악하고, 특정 개념을 검색하고, 출처가 붙은 답변을 확인하며, 정제된 학습 노트를 읽고, 복습 카드/퀴즈로 장기 기억을 강화할 수 있어야 한다.
- 핵심 지표:
  - 강의 처리 시간: 영상 길이의 0.3배 이하(RTX 4090 기준).
  - RAG 답변 출처 정확도: 수동 표본 50개 기준 90% 이상.
  - 자연어 질문 응답 시간: 일반 질의 30초 이내.
  - 정제 학습 노트 길이: 원본 대본 길이의 40~70%.
  - 학습 노트 핵심 개념 누락률: 수동 표본 검수 기준 5% 이하.
  - 출처 없는 환각 정보 비율: `(추론)` 표기 없이 본문에 들어간 신규 정보 2% 이하.
  - 맥락 기반 자동 교정 precision: 95% 이상.
  - 자동 교정 false positive 비율: 1% 이하.
  - Anki 카드 유효성: 직접 검수 기준 80% 이상.
  - 강의 시청 절감 시간: 전체 시청 대비 70% 이상 절감.
- 이번 버전의 목표: 강의 등록, 자막/STT 처리, OCR 입력 병합, 청킹/임베딩, 3단계 요약, RAG 챗봇, ScriptDigest 학습 노트 생성, Anki/퀴즈 산출물 생성까지 이어지는 통합 MVP 요구사항을 정의한다.

## 3. Non-Goals
- 이번에 하지 않을 것:
  - 강의 영상 자체의 재배포, 공유, 공개 라이브러리화.
  - 여러 사용자 간 공동 편집/협업 기능.
  - iOS/Android 네이티브 모바일 앱.
  - Zoom 등 실시간 스트리밍 강의 즉시 처리.
  - 자동 생성 노트를 공개 출판물처럼 외부 배포하는 기능.
- 의도적으로 제외한 범위:
  - MVP에서는 개인 로컬/개인 계정 기반 사용을 우선한다.
  - ScriptDigest는 STT/OCR을 직접 수행하지 않고 LectureDigest 전처리 파이프라인의 대본 세그먼트와 OCR 결과를 입력으로 받는다.
  - 강의 간 개념 그래프, Notion/HTML/PDF 내보내기, 모바일 앱, 고급 협업 기능은 후속 범위로 둔다.

## 4. User Personas
- 사용자 유형: "학습 누적자" — 호기심으로 강의를 사두지만 끝까지 보지 못하고, 필요한 때 핵심 내용을 빠르게 찾아 학습하고 싶은 1인 학습자.
- 사용자가 가진 문제:
  - 분야별 강의가 수십 개 이상 쌓여 있어 어떤 강의에 어떤 내용이 있는지 기억하기 어렵다.
  - 강의당 5~20시간 분량이라 전체 시청만으로 학습하기 어렵다.
  - 하루 학습 시간이 30분~1시간 정도로 단편적이다.
  - 자막이 없는 강의, 화면 코드가 중요한 강의, 전문 용어가 많은 강의에서 검색/복습 품질이 떨어진다.
  - 원본 대본은 filler word, 반복, 구어체, 말 끊김, STT 오류 때문에 읽기 피곤하다.
  - 짧은 요약은 빠르지만 예시, 맥락, 세부 논리를 놓친다.
- 주요 사용 맥락:
  - 특정 개념을 빠르게 찾고 싶을 때.
  - 강의를 보기 전 전체 구조와 난이도를 알고 싶을 때.
  - 특정 챕터를 영상 없이 학습 노트로 정독하고 싶을 때.
  - 이미 본 강의를 이동 시간에 Anki 카드나 퀴즈로 복습하고 싶을 때.
  - 여러 강의에 흩어진 같은 개념을 연결해서 보고 싶을 때.

## 5. Core User Flows
- 회원가입/로그인:
  - MVP는 로컬/개인 사용을 기본으로 하므로 회원가입은 필수가 아니다.
  - 클라우드 버전으로 확장할 경우 사용자는 로그인 후 본인 강의 라이브러리, 처리 작업, API 사용량, 학습 노트, 복습 산출물에만 접근한다.
- 핵심 기능 사용 흐름:
  1. 사용자가 영상 파일(mp4/mkv 등), 선택적 자막 파일(srt/vtt), 제목/강사/카테고리 메타데이터를 등록한다.
  2. 시스템은 자막이 있으면 파싱하고, 없으면 Whisper STT로 SRT 호환 세그먼트를 생성한다.
  3. 선택적으로 화자 분리와 화면 OCR을 수행하고, 모든 텍스트를 시간축에 맞춰 병합한다.
  4. 강의 텍스트를 60~90초 청크로 나누고 임베딩하여 Qdrant 등 벡터 DB에 저장한다.
  5. L1 섹션 요약, L2 챕터 요약, L3 강의 개요를 생성한다.
  6. 사용자는 요약을 읽거나 자연어로 질문하고, 답변에서 출처 타임스탬프와 원본 점프 링크를 확인한다.
  7. 사용자가 "학습 노트 생성"을 실행하면 ScriptDigest가 챕터 단위 대본을 정제, 구조화, 문어체 변환, 강조/보강, 검증하여 Markdown 노트를 만든다.
  8. 사용자는 노트의 타임스탬프, 용어집, 셀프 체크 질문, 교정 의심 마커를 확인하고 필요하면 원본으로 돌아간다.
  9. 사용자는 챕터별 Anki 카드와 퀴즈를 생성해 복습한다.
- 실패/빈 상태/예외 흐름:
  - 빈 라이브러리: 샘플 강의 등록 CTA와 지원 파일 형식을 보여준다.
  - 자막 없음: STT 작업으로 자동 전환하고 예상 처리 시간을 표시한다.
  - 입력 세그먼트 없음: 학습 노트를 만들지 않고 입력 누락 오류를 반환한다.
  - STT 의심 세그먼트 보정 실패: 원문을 유지하고 `[전사 의심: 원본]` 마커와 `transcription_warnings`를 기록한다.
  - LLM 교정 confidence 낮음: 본문은 유지하거나 검수 대기 상태로 저장하고 correction log에 후보를 남긴다.
  - 검색 결과 없음: 검색 범위, 카테고리 필터, 키워드 예시를 제안한다.
  - 출처 불충분 답변: 추론임을 명시하고 원본 근거가 부족하다고 표시한다.
  - 출력 검증 실패: 자동 수정 가능한 항목은 수정하고, 불가능하면 `status=flagged`로 저장한다.

## 6. Functional Requirements
| ID | Requirement | Priority | Acceptance Criteria |
|---|---|---|---|
| FR-001 | 강의 파일과 메타데이터를 등록하고 `lecture_id` 및 처리 상태를 생성한다. | Must | 영상 파일, 선택 자막, 제목, 강사, 카테고리를 입력하면 `pending` 상태의 강의가 생성된다. |
| FR-002 | 자막이 있으면 SRT/VTT를 파싱하고 타임스탬프를 보존한다. | Must | 자막 기반 강의는 STT를 건너뛰며 세그먼트별 시작/종료 시간이 유지된다. |
| FR-003 | 자막이 없으면 Whisper `large-v3` 또는 faster-whisper로 STT를 수행한다. | Must | 한국어 강의는 `--language ko`와 도메인 `initial_prompt`를 사용할 수 있고, 결과는 SRT 호환 세그먼트로 저장된다. |
| FR-004 | 강사/질문자 화자 분리를 옵션으로 지원한다. | Should | `pyannote.audio` 3.x 기반으로 화자 메타데이터를 저장하고, 강사 발화만 사용하는 옵션을 제공한다. |
| FR-005 | 슬라이드/코드 화면 OCR을 옵션으로 수행하고 자막 시간축에 병합한다. | Should | 키프레임 추출, 중복 제거, Vision OCR 결과가 `ocr_text`와 `slide_caption`으로 세그먼트에 연결된다. |
| FR-006 | 긴 강의 텍스트를 검색 가능한 청크로 나눈다. | Must | 기본 청크는 60~90초, 오버랩은 15초이며 `lecture_id`, `chapter`, `start_ts`, `end_ts`, `speaker`, `text`, `ocr_text`를 포함한다. |
| FR-007 | 청크 임베딩을 생성하고 벡터 DB에 저장한다. | Must | `text-embedding-3-large` 또는 `voyage-3`로 임베딩하고, Qdrant payload에 세그먼트 메타데이터가 포함된다. |
| FR-008 | 강의별 3단계 계층 요약을 생성한다. | Must | L1 섹션 요약, L2 챕터 요약, L3 강의 개요/TL;DR/학습 목표가 생성되고 조회 가능하다. |
| FR-009 | 자연어 질의응답 RAG 챗봇을 제공한다. | Must | BM25+dense hybrid 검색, 선택적 reranker, 상위 근거 청크 기반 답변을 생성한다. |
| FR-010 | 답변에는 출처 인용과 원본 점프 링크를 포함한다. | Must | 모든 답변은 `[강의명 - 챕터 - 12:34]` 형식의 근거와 재생 위치 링크를 표시한다. |
| FR-011 | 멀티 강의 검색과 메타데이터 필터를 지원한다. | Must | 전체 강의 통합 검색이 기본이며 강의, 카테고리, 시간 범위 필터를 적용할 수 있다. |
| FR-012 | ScriptDigest 입력으로 대본 세그먼트 배열과 강의 메타데이터를 받는다. | Must | `lecture_id`, `lecture_title`, `chapter_title`, `category`, `instructor`, `[{start_ts,end_ts,text,speaker?}]`가 없으면 명확한 오류를 반환한다. |
| FR-013 | ScriptDigest 선택 입력으로 OCR 텍스트, 도메인 용어집, 사용자 톤 선호를 받는다. | Must | OCR은 시간축 정렬 데이터로 받고, 톤은 `formal`, `casual`, `keep_original` 중 하나이며 기본값은 `formal`이다. |
| FR-014 | 학습 노트 생성 권장 단위를 챕터 단위로 제한한다. | Must | 권장 범위는 5~30분 또는 약 3,000~15,000 토큰이며, 초과 시 사전 분할 경고를 낸다. |
| FR-015 | STT 무결성 검증을 정제 전 수행한다. | Must | 미완성 문장, 고립 조사, 숫자 단편, 음운 혼동 후보, 세그먼트 길이 이상치를 탐지한다. |
| FR-016 | STT 의심 세그먼트를 단계적으로 보정한다. | Must | 인접 세그먼트 포함 `gpt-4o-mini` 1차, `gpt-4o` 2차, 실패 시 원문 유지+마커+frontmatter 카운트를 적용한다. |
| FR-017 | filler word와 즉시 반복을 제거한다. | Must | 의미 없는 "음", "어", "그", "그러니까", "뭐냐면", "이제", "자" 등을 제거하되 의도적 강조 반복은 보존한다. |
| FR-018 | 도메인 용어집 기반 전사 오류를 보정한다. | Must | 사전 등록 용어와 음운 유사도 기준으로 명확한 오류만 보정하고 애매한 경우 플래그 처리한다. |
| FR-019 | 맥락 기반 오탈자 자동 교정을 수행한다. | Must | Pass A는 강의 도메인/핵심 주제/빈출어를 추출하고, Pass B는 후보를 탐지하며, Pass C는 confidence에 따라 자동 교정/검수/유지를 결정한다. |
| FR-020 | 자동 교정 false positive 방지 규칙을 적용한다. | Must | confidence 0.9 이상만 자동 교정하고, 챕터당 교정 상한, 고유명사/숫자/생소어 보호 규칙을 적용한다. |
| FR-021 | 맥락 기반 교정을 모든 노트 출력 섹션에 일관 적용한다. | Must | 본문뿐 아니라 학습 목표, 핵심 요약, 용어집, 셀프 체크, frontmatter 관련 텍스트까지 동일 교정 사전을 사용한다. |
| FR-022 | 원본 매핑을 보존한다. | Must | 각 단락과 주요 문장은 원본 segment id, 시작/종료 타임스탬프와 연결된다. |
| FR-023 | 의미 단락 분할과 자동 제목 부여를 수행한다. | Must | 주제 변화 기준으로 단락을 나누고, H2/H3 제목은 중복 없이 내용과 일치해야 한다. |
| FR-024 | 챕터 수준 학습 노트 구조를 생성한다. | Must | 학습 목표는 단일 소스로 만들고, 핵심 요약은 TL;DR, 핵심 개념, 복습 포인트, 챕터 요약으로 분해한다. |
| FR-025 | 논리 패턴을 시각적 Markdown으로 변환한다. | Should | 비교는 표, 절차는 번호 목록, 코드 설명은 코드 블록, 관계 흐름은 mermaid 제안으로 변환할 수 있다. |
| FR-026 | 구어체를 문어체 학습 본문으로 변환한다. | Must | filler를 제거하고 문장을 정돈하되, 강사의 중요한 비유/경고/강조 표현은 보존한다. |
| FR-027 | Rewrite 검증 게이트를 제공한다. | Must | `formal` 기준 구어체 잔존, 문장 길이, 불필요한 존댓말 반복, 스타일 위반을 검사하고 임계치 초과 시 재시도한다. |
| FR-028 | 화자 모놀로그 통합을 지원한다. | Should | 강사 단독 강의는 화자 라벨을 제거하고 자연스러운 본문으로 통합하며, 인터뷰/대화형 강의는 옵션으로 유지한다. |
| FR-029 | 한국어 형태소 분석을 수행한다. | Must | Kiwi(`kiwipiepy`)를 우선 사용해 표제어, 품사, 조사 분리, 받침 여부, 동의어/이형 통합을 처리한다. |
| FR-030 | 핵심 용어 강조와 용어집을 생성한다. | Must | 본문 첫 등장 핵심 용어는 굵게 표시하고, 정의 패턴이 1회 이상 검출된 용어만 용어집에 등재한다. |
| FR-031 | 용어집 fallback을 금지한다. | Must | 원문 근거가 없는 정의는 임의 생성하지 않으며, LLM 부연이 필요하면 `(추론)`을 명시한다. |
| FR-032 | 표준 콜아웃을 생성한다. | Should | 예시, 주의, 정의, 화면 메모 등은 정해진 콜아웃 형식으로 출력하고, 화면 메모는 OCR 입력이 있을 때만 사용한다. |
| FR-033 | 셀프 체크 질문을 생성한다. | Should | 챕터 또는 단락 끝에 답 없는 회상 질문 3~5개를 생성한다. |
| FR-034 | 학습 노트 출력 검증 게이트를 실행한다. | Must | 헤더 중복, 헤더-내용 불일치, 길이, 톤, 표제어/조사, 용어집 fallback, 교차 적용, 학습 목표 단일 소스, STT 마커 수를 검사한다. |
| FR-035 | Markdown 학습 노트와 frontmatter를 생성한다. | Must | frontmatter에는 입력/모델/교정/검증/품질 메타데이터를 포함하고, 본문은 표준 섹션 구조를 따른다. |
| FR-036 | Anki 카드 덱을 자동 생성한다. | Should | 챕터 요약/세그먼트/학습 노트에서 Cloze, Q&A, 코드 카드 후보를 만들고 `.apkg` 또는 AnkiConnect로 내보낸다. |
| FR-037 | 챕터별 자동 퀴즈를 생성한다. | Should | 문항은 문제, 4지선다, 정답, 해설, 원본 출처를 포함하며 오답 시 원본 구간으로 이동할 수 있다. |
| FR-038 | 강의 간 개념 그래프를 선택 기능으로 제공한다. | Could | 핵심 개념과 관계(`is-a`, `uses`, `prerequisite-of`)를 추출하고 Obsidian/Neo4j 등으로 내보낼 수 있다. |
| FR-039 | 비동기 작업 상태, 재시도, 단계별 재개를 지원한다. | Must | STT, OCR, 임베딩, 요약, 노트 생성, 카드/퀴즈 생성은 큐 기반으로 처리되고 실패 단계부터 재시작 가능하다. |
| FR-040 | 단계별 캐시와 correction/validation log를 저장한다. | Must | 동일 입력/모델/프롬프트 버전은 재사용하고, 모든 자동 교정과 검증 실패는 추적 가능해야 한다. |

## 7. Data Requirements
- 주요 엔티티:
  - `lectures`: 강의 기본 정보, 파일 위치, 길이, 처리 상태.
  - `chapters`: 챕터 제목, 시작/종료 시간, L2 요약.
  - `segments`: 원본 자막/STT 텍스트, OCR 텍스트, 화자, L1 요약.
  - `embeddings`: Qdrant payload의 `segment_id` 기반 벡터.
  - `lecture_notes`: 챕터 단위 최종 Markdown, frontmatter, 상태, 모델 버전, 검증 결과.
  - `note_sections`: 단락별 제목, 순서, 본문, 원본 segment id, 시작/종료 시간.
  - `note_glossary`: 용어, 정의, 첫 등장 타임스탬프, 등장 위치.
  - `note_self_check`: 셀프 체크 질문과 범위(section/chapter).
  - `correction_log`: STT 무결성, 용어집, 맥락 교정, 교차 적용 교정 내역.
  - `lecture_context`: 도메인, 핵심 주제, 빈출어, 고유명사, 언어 register.
  - `morphology_lemmas`: Kiwi 분석 결과, 표제어, 품사, 표면형, 등장 횟수, 받침 여부.
  - `validation_log`: 헤더, 길이, 스타일, 용어집, 교차 적용 등 검증 결과.
  - `flashcards`: 카드 유형, 앞면/뒷면, 난이도, 출처 시간.
  - `quizzes`: 문제, 보기, 정답, 해설, 출처.
  - `concepts`, `concept_links`, `concept_relations`: 선택 기능인 개념 그래프 데이터.
- 저장해야 하는 데이터:
  - 원본 파일 경로 또는 객체 스토리지 키.
  - 자막/STT 세그먼트와 타임스탬프.
  - OCR 텍스트와 슬라이드 캡션.
  - 임베딩 모델명, 생성 시각, 청크 설정.
  - L1/L2/L3 요약, RAG 인용, 학습 노트, 카드, 퀴즈, 생성 모델 버전.
  - 학습 노트 단계별 중간 산출물(cleaned, structured, rewritten, augmented, validated).
  - 자동 교정 원문/수정안/confidence/reasoning/applied 상태.
  - 작업 상태, 오류 로그, 재시도 이력, 비용/토큰 사용량.
- 민감정보 여부:
  - 강의 파일, 대본, OCR 텍스트, 학습 노트는 저작권이 있는 개인 학습 자료일 수 있다.
  - 학습 기록, 질문 내용, 도메인 용어집, API 키, 로컬 파일 경로는 민감정보로 취급한다.
- 보존/삭제 정책:
  - 사용자가 강의를 삭제하면 원본 파일 참조, 세그먼트, 임베딩, 요약, 노트, 카드, 퀴즈, 교정/검증 로그, 캐시를 함께 삭제한다.
  - LLM/OCR 호출 결과는 재현성과 비용 절감을 위해 캐시하되, 사용자 삭제 요청 시 함께 제거한다.
  - 프롬프트/모델 버전이 바뀌면 단계별 캐시를 무효화하거나 재생성 후보로 표시한다.
  - API 키와 인증 정보는 문서/로그에 평문 저장하지 않는다.

## 8. Permissions & Security
- 권한 모델:
  - MVP는 단일 사용자 로컬 권한 모델을 기본으로 한다.
  - 클라우드 확장 시 사용자별 강의 라이브러리, 대본, 노트, 교정 로그, 복습 산출물을 엄격히 분리한다.
- 접근 제한:
  - 원본 영상, 자막, OCR 이미지, 임베딩, 요약, 학습 노트, correction log는 소유 사용자만 접근할 수 있다.
  - 검수 UI는 사용자가 본인 강의의 교정 후보만 승인/기각할 수 있어야 한다.
  - API 키는 환경 변수 또는 안전한 비밀 저장소에서만 읽는다.
  - 외부 API로 전송되는 데이터 범위(텍스트, 프레임, OCR 결과)를 설정에서 확인할 수 있어야 한다.
- 보안상 금지할 동작:
  - 강의 원본, 추출 대본, 자동 생성 노트를 다른 사용자에게 자동 공유하거나 공개 링크로 노출하지 않는다.
  - 로그에 API 키, 전체 원본 대본, 결제/계정 정보를 남기지 않는다.
  - 출처 없는 답변이나 근거 없는 LLM 부연을 원본 강의 내용처럼 표시하지 않는다.
  - confidence가 낮은 교정을 사용자 몰래 본문에 확정 적용하지 않는다.
  - 저작권이 있는 강의를 재배포 가능한 콘텐츠로 내보내지 않는다.

## 9. UX Requirements
- 필수 화면:
  - 강의 라이브러리 및 카테고리 목록.
  - 강의 등록/업로드 화면.
  - 처리 진행 상태 화면(STT, OCR, 임베딩, 요약, 노트 생성 단계별).
  - 강의 상세 화면(개요, 챕터, 섹션 요약, 원본 점프 링크).
  - 검색/RAG 챗 화면(인용, 필터, 관련 구간).
  - 학습 노트 생성 요청 화면(입력 챕터, 톤, OCR 사용 여부, 용어집 선택).
  - Markdown 노트 미리보기 화면(타임스탬프, 콜아웃, 용어집, 셀프 체크 표시).
  - 교정 검수 화면(원문, 수정안, confidence, reasoning, 승인/기각).
  - 검증 결과 패널(헤더 중복, 스타일 위반, 용어집 보류, STT 의심 마커).
  - Anki/퀴즈 생성 및 내보내기 화면.
  - 설정 화면(API 키, 모델, 비용 제한, 로컬/클라우드 처리 범위).
- 로딩/빈/오류 상태:
  - 장기 작업은 현재 단계, 예상 남은 시간, 재시도 버튼을 표시한다.
  - 빈 검색 결과는 필터 초기화와 유사 키워드 제안을 제공한다.
  - 입력 세그먼트가 없으면 "대본 입력이 필요합니다" 상태를 표시한다.
  - 검증 실패는 실패 항목과 자동 수정 여부를 분리해 보여준다.
  - 교정 후보가 없으면 "검수할 교정 후보 없음" 상태를 표시한다.
  - OCR이 없으면 화면 메모 섹션을 만들지 않고 해당 옵션 비활성 상태를 보여준다.
- 접근성:
  - 키보드만으로 검색, 챕터 이동, 답변 출처 열기, 교정 승인/기각, 재시도 실행이 가능해야 한다.
  - 타임스탬프, 인용, 의심 마커는 색상 외 텍스트 레이블로도 구분한다.
  - Markdown 미리보기와 원본 대본 비교는 스크린 리더가 읽을 수 있는 구조를 유지한다.
- 모바일/데스크톱 기준:
  - MVP는 데스크톱 웹/로컬 UI 우선이다.
  - 모바일은 읽기, 검색, 간단한 검수 정도의 반응형 지원만 목표로 하고, 대용량 업로드/관리 경험은 데스크톱 기준으로 설계한다.

## 10. Observability & Reliability
- 필요한 로그:
  - 강의 등록, STT 시작/완료, OCR 시작/완료, 청킹/임베딩, 요약, RAG 질의, 노트 생성, 카드/퀴즈 생성 단계별 로그.
  - 모델명, 프롬프트 버전, 토큰 사용량, API 비용 추정, 처리 시간.
  - STT 의심 세그먼트 수, 자동 보정 수, 실패 마커 수.
  - 맥락 교정 Pass A/B/C 후보 수, 자동 적용 수, 검수 대기 수.
  - Rewrite 재시도 횟수와 스타일 위반 항목.
  - 용어집 등재/보류 사유.
  - 출력 검증 결과와 자동 수정 이력.
  - 실패 단계, 원본 예외 메시지, 재시도 횟수, 사용자에게 표시한 오류 코드.
- 실패 시 보여줄 메시지:
  - "STT 처리에 실패했습니다. 원본 파일을 읽을 수 없거나 오디오 트랙이 없습니다."
  - "입력 대본 세그먼트가 없어 노트를 생성할 수 없습니다."
  - "전사 의심 구간 일부를 자동 보정하지 못했습니다. 노트에 마커로 표시했습니다."
  - "자동 교정 confidence가 낮아 사용자 검수가 필요합니다."
  - "검색 근거가 충분하지 않아 답변을 생성하지 않았습니다. 검색 범위를 넓혀보세요."
  - "출력 검증을 통과하지 못했습니다. 헤더 중복 또는 스타일 위반을 확인하세요."
  - "LLM 호출 한도에 도달했습니다. 비용 제한을 높이거나 나중에 다시 시도하세요."
- 재시도/복구 기준:
  - 각 처리 단계는 idempotent하게 설계해 실패 단계부터 재개한다.
  - STT/OCR/LLM/ScriptDigest 단계별 결과는 입력 해시, 모델 버전, 프롬프트 버전 기준으로 캐시한다.
  - 자동 교정은 원문과 수정안을 모두 저장해 되돌릴 수 있어야 한다.
  - validation 실패는 자동 수정 가능한 항목을 1차 수정한 뒤 재검증한다.
  - API 일시 실패는 제한된 횟수로 backoff 재시도한다.
  - 재시도 후에도 실패하면 부분 결과를 보존하고 사용자에게 검수/재처리 선택지를 제공한다.

## 11. Performance / Cost
- 응답 시간 기준:
  - 일반 RAG 질의는 30초 이내 답변을 목표로 한다.
  - 강의 처리 전체 시간은 영상 길이의 0.3배 이하를 목표로 한다.
  - 30분 분량 챕터의 전체 학습 노트 생성은 5분 이내를 목표로 한다.
  - 강의 상세 화면의 저장된 요약/챕터/노트 조회는 2초 이내에 표시한다.
  - 교정 후보 목록과 검증 결과는 3초 이내에 열람 가능해야 한다.
- API/LLM 비용 제한:
  - L1 섹션 요약과 대량 호출은 `gpt-4o-mini` 등 저비용 모델을 우선한다.
  - L2/L3 요약, RAG 최종 답변, ScriptDigest Rewrite/보강처럼 품질이 중요한 단계는 `gpt-4o` 또는 `gpt-4.1` 등 고품질 모델을 사용한다.
  - STT 무결성 보정은 검출 패턴에 매칭된 세그먼트만 LLM 호출한다.
  - Cleanup 기본 작업은 규칙 기반을 우선하고 필요한 경우에만 LLM을 호출한다.
  - OCR은 장면 변화 기반 키프레임과 중복 제거 후 수행한다.
  - 임베딩과 LLM 호출 결과는 캐시하여 같은 입력을 반복 호출하지 않는다.
  - 30분 분량 챕터의 ScriptDigest LLM 비용은 $0.30 이하를 목표로 한다.
- 확장 고려사항:
  - 큐는 Redis+Celery 또는 Prefect 기반으로 시작하고, 작업량 증가 시 워커를 수평 확장한다.
  - 벡터 DB는 Qdrant를 기본으로 하되 Chroma, pgvector 대체를 열어둔다.
  - ScriptDigest는 중간 표현(IR)을 두어 Markdown 외 Obsidian, Notion, HTML/PDF 렌더러를 붙일 수 있게 한다.
  - prompt는 YAML 파일과 버전 태그로 관리해 A/B 테스트와 롤백이 가능해야 한다.
  - 장기적으로 Next.js UI, 객체 스토리지, 사용자별 비용 한도, 모델별 라우팅을 고려한다.

## 12. Release Scope
- MVP:
  - Phase 0: 보유 강의 1개와 1챕터를 기준으로 NotebookLM/단일 LLM 호출/수동 골든 노트를 비교해 직접 개발할 차별 영역을 확인한다.
  - Phase 1: 강의 등록 CLI 또는 최소 UI, 자막/STT 처리, 청킹, 임베딩, Qdrant 저장, 단순 RAG 챗, L1/L2/L3 요약을 구현한다.

## 13. Risks & Open Questions
- 리스크:
  - Whisper STT가 전문 용어, 한국어+코드 혼합 강의에서 오인식할 수 있다.
  - STT 오류가 학습 노트 생성 단계까지 전달되면 잘못된 본문이 만들어질 수 있다.
  - LLM API 비용이 긴 강의와 반복 생성에서 급증할 수 있다.
  - 청크 경계가 부적절하면 RAG 답변의 근거가 끊길 수 있다.
  - OCR은 화면 변화가 많은 코드 강의에서 비용과 중복이 커질 수 있다.
  - LLM이 원본에 없는 내용을 본문에 섞어 넣으면 노트 신뢰도가 떨어진다.
  - 구어체를 과도하게 문어체로 바꾸면 강사의 뉘앙스와 중요한 강조가 사라질 수 있다.
  - 단락 분할이 잘못되면 한 주제가 여러 단락으로 찢기거나 서로 다른 주제가 섞일 수 있다.
  - 맥락 기반 오탈자 교정이 멀쩡한 단어를 바꾸는 false positive가 발생할 수 있다.
  - 출처 없는 추론이나 과도한 요약은 사용자의 신뢰를 떨어뜨릴 수 있다.
  - 저작권이 있는 강의 자료를 외부 API로 전송하거나 공유하는 데 법적/계약상 제한이 있을 수 있다.
  - NotebookLM 등 기존 도구가 충분히 좋다면 직접 개발 범위를 줄여야 할 수 있다.
- 아직 결정 안 된 것:
  - 로컬 우선 처리와 클라우드 처리의 경계.
  - MVP UI를 Streamlit으로 빠르게 만들지, Next.js로 제품형 UI를 바로 만들지.
  - Anki와 퀴즈 중 어떤 능동학습 기능을 먼저 출시할지.
  - OCR 결과를 어디까지 학습 노트에 넘기고, 어디까지 RAG 검색 대상으로 삼을지.
  - 모델/프롬프트 변경 시 기존 요약, 노트, 카드, 퀴즈를 자동 재생성할지, 사용자 요청 시에만 재생성할지.
  - 정제된 학습 노트를 RAG 인덱스에 추가할지, 원본 세그먼트만 검색 대상으로 유지할지.
  - 챕터 정보가 없는 강의를 어떤 기준으로 자동 분할할지.
  - `speaker_mode=dialogue`를 언제 자동 활성화할지.
  - 화면 메모가 긴 경우 본문 콜아웃으로 넣을지, 부록으로 분리할지.
  - confidence 0.7~0.9 교정 후보를 본문에 선적용할지, 검수 전에는 원문 유지할지.
