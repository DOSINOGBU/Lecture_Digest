# Product Context

LectureDigest는 개인이 보유한 온라인 강의를 검색 가능한 지식베이스와 학습 산출물로 바꾸는 학습 가속화 도구입니다. 이 문서는 기능을 만들 때 제품 목적, 사용자, 성공 기준을 오해하지 않도록 PRD의 제품 맥락만 요약합니다.

## Problem

1인 학습자는 코딩, 마케팅, 디자인, 자기계발 등 여러 분야의 강의를 많이 보유하지만 강의가 길고 많아 끝까지 시청하기 어렵습니다. 단순 요약은 빠르지만 예시, 맥락, 세부 논리를 놓치기 쉽고, 원본 대본은 구어체, 반복, filler word, 말 끊김, STT 오류 때문에 그대로 읽기 어렵습니다.

LectureDigest는 사용자가 강의를 처음부터 끝까지 보지 않아도 전체 구조를 파악하고, 필요한 개념을 검색하며, 출처가 붙은 답변과 정제된 학습 노트, 복습 산출물로 학습을 이어갈 수 있게 해야 합니다.

## Target Users

| 사용자 | 목표 | 불편 |
|---|---|---|
| 1인 학습자 | 보유 강의를 빠르게 탐색하고 필요한 개념을 학습 | 강의 수가 많고 길어 전체 시청이 비현실적 |
| 시간 제약이 큰 학습자 | 하루 30분~1시간 안에 핵심 내용을 복습 | 긴 영상보다 챕터 단위 노트와 카드가 필요 |
| 전문 강의 학습자 | 코드, 화면, 전문 용어가 포함된 강의를 검색 | STT 오류, OCR 누락, 용어 오인식으로 검색 품질 저하 |

## Core Jobs

- 강의 파일, 선택 자막, 제목/강사/카테고리 메타데이터를 등록한다.
- 자막 또는 STT 결과를 시간축이 있는 세그먼트로 만들고, 선택적으로 OCR/화자 정보를 병합한다.
- 강의를 청크화, 임베딩, 요약하여 검색 가능한 지식베이스로 만든다.
- RAG 답변에는 출처 인용과 원본 점프 링크를 제공한다.
- 챕터 단위 ScriptDigest 학습 노트를 생성하되 원본 매핑, 검증 결과, 교정 이력을 보존한다.
- 능동 복습은 Anki 카드를 먼저 제공하고, 퀴즈는 후속 기능으로 확장한다.

## Product Principles

- 원본 근거가 없는 정보는 원본 내용처럼 보여주지 않습니다. 필요한 경우 `(추론)`으로 명시합니다.
- 사용자는 항상 출처 타임스탬프와 원본으로 돌아가는 경로를 확인할 수 있어야 합니다.
- 자동 교정은 신뢰도가 충분할 때만 적용하고, 낮은 confidence 후보는 검수 대상으로 남깁니다.
- 긴 작업은 현재 단계, 실패 지점, 재시도 가능 여부를 보여줍니다.
- MVP는 개인 로컬/개인 계정 기반 사용을 우선하며 공유, 협업, 공개 배포를 목표로 하지 않습니다.

## Success Criteria

| 기준 | 목표 | 확인 방법 |
|---|---|---|
| 처리 시간 | 강의 처리 전체 시간이 영상 길이의 0.3배 이하(RTX 4090 기준) | 대표 강의 처리 시간 측정 |
| RAG 출처 정확도 | 수동 표본 50개 기준 90% 이상 | 질문-답변-출처 수동 검수 |
| RAG 응답 시간 | 일반 질의 30초 이내 | 수동 시나리오와 로그 타이밍 |
| 노트 압축률 | 정제 노트가 원본 대본 길이의 40~70% | 원본/노트 토큰 또는 문자 수 비교 |
| 핵심 개념 누락률 | 수동 검수 기준 5% 이하 | 골든 노트 또는 표본 검수 |
| 출처 없는 신규 정보 | `(추론)` 표기 없는 신규 정보 2% 이하 | 노트/답변 표본 검수 |
| 자동 교정 품질 | precision 95% 이상, false positive 1% 이하 | correction log 검수 |
| 복습 산출물 품질 | Anki 카드 유효성 80% 이상 | 카드 표본 검수 |

## MVP Scope

- Phase 0: 보유 강의 1개와 1챕터로 NotebookLM, 단일 LLM 호출, 수동 골든 노트를 비교해 직접 개발할 차별 영역을 확인합니다.
- Phase 1: Streamlit 기반 최소 UI와 단일 프로세스 파이프라인으로 강의 등록, 자막/STT 처리, 청킹, 임베딩, Qdrant 저장, 단순 RAG 챗, L1/L2/L3 요약을 구현합니다.
- Phase 1-ScriptDigest: filler 제거, 반복 정리, 용어집 기반 보정, 의미 단락화, 문어체 rewrite, Markdown frontmatter, 단계별 캐시를 구현합니다.

MVP 종료 기준은 사용자가 강의를 등록하고, 요약을 읽고, 질문하고, 출처 위치로 이동하고, 챕터 학습 노트를 읽어 핵심 내용을 이해할 수 있는 상태입니다.

## Non-Goals

- 강의 영상 자체의 재배포, 공유, 공개 라이브러리화.
- 여러 사용자 간 공동 편집/협업.
- iOS/Android 네이티브 모바일 앱.
- Zoom 등 실시간 스트리밍 강의 즉시 처리.
- 자동 생성 노트를 공개 출판물처럼 외부 배포하는 기능.
- 강의 간 개념 그래프, Notion/HTML/PDF 내보내기, 모바일 앱, 고급 협업 기능은 후속 범위입니다.

## Initial Decisions

| 질문 | 현재 결정 | 영향 |
|---|---|---|
| 로컬 우선 처리와 클라우드 처리의 경계는 어디인가? | 초기에는 로컬 처리 중심, LLM 호출만 클라우드 | 보안, 저장소, 배포 구조에 영향 |
| MVP UI는 Streamlit/CLI로 빠르게 갈지, Next.js로 시작할지? | Streamlit 추천 | 프론트엔드 구조와 개발 순서에 영향 |
| 큐/워커 구조는 무엇으로 시작할지? | 초기에는 단일 CLI/단일 프로세스 | 재시도, 작업 상태, 배포 구조에 영향 |
| Anki와 퀴즈 중 무엇을 먼저 출시할지? | Anki 먼저 | MVP 이후 우선순위와 데이터 모델에 영향 |
| OCR 결과를 노트와 RAG에 어디까지 반영할지? | 원문 OCR은 보관하고, 정제본만 노트/RAG에 반영 | 비용, 검색 품질, 노트 신뢰도에 영향 |
| 모델/프롬프트 변경 시 산출물을 자동 재생성할지? | 자동 재생성하지 않고 수동 재생성 버튼 제공 | 비용, 캐시 무효화, 사용자 경험에 영향 |
| 정제 노트를 RAG 인덱스에 포함할지? | 포함 추천 | 답변 품질과 원본 근거 정책에 영향 |
