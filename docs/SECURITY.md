# Security

## MVP BYOK Secret Handling

- MVP API 키는 BYOK를 기본으로 하며 환경 변수 또는 로컬 비밀 저장소에서만 읽습니다.
- `.env` 같은 로컬 설정 파일은 커밋하지 않고, 예시 파일에는 변수명과 설명만 둡니다.
- API 키, 계정 식별자, 결제 정보, 전체 로컬 파일 경로는 로그와 산출물에 남기지 않습니다.
- OpenAI STT, Vision OCR, LLM 호출에는 필요한 최소 텍스트, 오디오, 프레임만 전송합니다.
- 외부 API 전송 범위는 명령 실행 전 확인 가능한 설정/preview로 노출하는 것을 목표로 합니다.
- 키 노출이 의심되면 즉시 제공자 콘솔에서 키를 폐기하고 새 키로 교체합니다.

LectureDigest는 사용자의 강의 원본, 대본, OCR 텍스트, 학습 노트, 질문 로그를 다룹니다. MVP는 로컬/개인 사용을 우선하고 초기 클라우드 범위는 LLM 호출만 허용합니다. 파일 처리, 외부 API 호출, 향후 클라우드 확장을 고려해 보안 경계를 분명히 둡니다.

## Sensitive Data

- API 키, 토큰, 비밀번호, 결제/계정 정보는 코드나 로그에 남기지 않습니다.
- 강의 파일, 자막/STT 대본, OCR 결과, 학습 노트, 카드, 퀴즈는 저작권이 있는 개인 학습 자료로 취급합니다.
- 질문 내용, 도메인 용어집, 학습 기록, 로컬 파일 경로는 민감정보로 취급합니다.
- `.env.example`에는 값이 아니라 변수명과 설명만 둡니다.

## Permission Model

| 단계 | 원칙 |
|---|---|
| MVP 로컬 | 단일 사용자 로컬 권한 모델을 기본으로 하며, OS 파일 권한과 로컬 설정을 신뢰 경계로 둠 |
| 초기 클라우드 호출 | LLM 호출만 허용하고 강의 파일, 원문 OCR, 벡터 저장소는 로컬 중심으로 유지 |
| 개인 계정 확장 | 사용자별 강의 라이브러리, 대본, 노트, 교정 로그, 복습 산출물을 분리 |
| 클라우드 확장 | 서버 측 인증/권한 검사를 필수로 하고 객체 스토리지, 작업 큐, 벡터 DB 접근을 사용자 단위로 제한 |

## Access Rules

| 자산 | 접근 원칙 |
|---|---|
| 원본 영상/자막/OCR 이미지 | 소유 사용자만 접근 |
| 임베딩과 요약 | 원본 강의와 같은 권한으로 보호 |
| 학습 노트와 복습 산출물 | 자동 공유 금지, 사용자 명시 내보내기만 허용 |
| correction log | 본인 강의의 후보만 승인/기각 가능 |
| API 키 | 환경 변수 또는 안전한 비밀 저장소에서만 읽음 |
| 외부 API 전송 데이터 | 설정에서 전송 범위를 확인할 수 있어야 함 |

## Forbidden Actions

- 강의 원본, 추출 대본, 자동 생성 노트를 다른 사용자에게 자동 공유하거나 공개 링크로 노출하지 않습니다.
- 로그에 API 키, 전체 원본 대본, 결제/계정 정보, 불필요한 파일 경로를 남기지 않습니다.
- 출처 없는 답변이나 근거 없는 LLM 부연을 원본 강의 내용처럼 표시하지 않습니다.
- confidence가 낮은 교정을 사용자 몰래 본문에 확정 적용하지 않습니다.
- 저작권이 있는 강의를 재배포 가능한 콘텐츠로 내보내지 않습니다.
- 외부 API에 전송할 필요가 없는 프레임, 대본, OCR 결과를 과도하게 보내지 않습니다.
- 초기 MVP에서는 STT/OCR 처리를 클라우드로 보내지 않고, 필요한 LLM 입력 텍스트만 최소 전송합니다.

## Input And Upload Checks

- 파일 업로드는 확장자, 크기, 콘텐츠 타입, 읽기 가능 여부를 검증합니다.
- 지원 대상 후보는 영상 파일(mp4/mkv 등), 자막(srt/vtt), 선택적 메타데이터입니다.
- 경로 입력은 정규화하고 프로젝트/사용자 허용 범위를 벗어나는 접근을 막습니다.
- 외부 API 요청에 들어가는 텍스트는 최소 범위로 잘라 보내고, 민감정보가 섞일 수 있음을 전제로 로그를 제한합니다.

## Security Review Checklist

- 민감정보가 로그에 남지 않는가?
- 사용자 입력이 경계에서 검증되는가?
- 권한 검사가 클라이언트에만 있지 않은가?
- 에러 메시지가 내부 구조와 파일 경로를 과도하게 드러내지 않는가?
- 외부 입력이 그대로 SQL, 셸, HTML, 경로에 들어가지 않는가?
- 새 의존성이 보안 권고, 라이선스, 모델 다운로드 정책 측면에서 검토되었는가?
- 외부 API로 전송되는 데이터 범위와 비용 영향이 문서화되었는가?

## Threat Model Notes

| 자산 | 위협 | 1차 방어 |
|---|---|---|
| 강의 원본과 대본 | 무단 조회, 재배포 | 접근 권한 검사, 자동 공유 금지 |
| OCR 이미지/텍스트 | 화면 속 비밀값 유출 | 최소 전송, 로그 제한, 삭제 연동 |
| API 키 | 노출, 오용 | 환경변수/비밀 저장소, 마스킹 로그 |
| LLM 산출물 | 환각, 근거 없는 교정 | 출처 표시, confidence 정책, correction log |
| 벡터 DB | 사용자 간 자료 혼입 | 사용자/강의 payload 분리, 삭제 시 벡터 제거 |
| 파일 경로 | 경로 탐색, 로컬 정보 노출 | 경계 검증, 에러 메시지 최소화 |
