# Runbook

장애나 운영 이슈가 발생했을 때 바로 실행할 대응 절차를 기록합니다. 현재는 구현 전 하네스 단계이므로 구체 명령은 스택 확정 후 채웁니다.

## First Response

1. 영향 범위와 시작 시각을 확인합니다.
2. 최근 배포, 모델/prompt 버전, 설정 변경을 확인합니다.
3. 로그와 지표에서 실패 단계를 좁힙니다.
4. 부분 결과 보존 여부와 재시도 가능 여부를 확인합니다.
5. 완화 조치와 롤백 가능성을 판단합니다.

## Common Incidents

| 증상 | 우선 확인 | 완화 |
|---|---|---|
| STT 실패 | 파일 읽기 가능 여부, 오디오 트랙, 모델 로그 | 자막 입력 요청, 재시도, 실패 상태 저장 |
| OCR 비용 급증 | 키프레임 수, 중복 제거 결과 | OCR 비활성화, 샘플링 간격 조정 |
| RAG 근거 부족 | 필터, 검색 쿼리, 청크 수, 인덱스 상태 | 검색 범위 확장, 답변 생성 거부 |
| 출처 없는 답변 증가 | prompt 버전, 인용 수, 검증 로그 | 답변 차단 기준 강화, prompt rollback |
| 노트 검증 실패 | 실패 규칙, 자동 수정 가능 여부 | 자동 수정 후 재검증, `flagged` 저장 |
| 교정 false positive | correction log, confidence 분포 | 자동 적용 임계값 상향, 후보 검수로 전환 |
| LLM 비용 한도 도달 | 토큰 사용량, 반복 호출, 캐시 적중률 | 비용 제한 상향 요청 또는 나중에 재시도 |
| 모델/prompt 변경 후 stale 산출물 발생 | 변경된 버전, 영향받은 강의/노트/인덱스 | 자동 재생성하지 않고 수동 재생성 안내 |

## After Action

- 원인, 영향, 탐지 시간, 복구 시간을 기록합니다.
- 재발 방지 항목을 checklist 또는 automation 후보로 옮깁니다.
- 모델/prompt/캐시 변경이 원인이었다면 영향을 받은 산출물과 재생성 필요 여부를 기록합니다.
- 재생성이 필요하면 자동으로 실행하지 않고 사용자에게 수동 재생성 범위와 예상 비용을 제시합니다.
- 사용자가 다시 결정해야 하는 비용, 보안, 품질 정책이 있으면 관련 문서의 Open Questions에 추가합니다.
