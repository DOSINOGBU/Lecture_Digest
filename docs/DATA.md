# Data

LectureDigest의 데이터는 원본 강의 자료, 대본, OCR, 학습 노트, 교정 로그처럼 되돌리기 어렵고 민감한 개인 학습 자료를 포함합니다. 데이터 변경은 코드 변경보다 되돌리기 어렵기 때문에 이 문서를 우선합니다.

## Core Entities

| 엔티티 | 목적 | 주요 필드 |
|---|---|---|
| `lectures` | 강의 기본 정보와 처리 상태 | 제목, 강사, 카테고리, 파일 위치, 길이, 상태 |
| `chapters` | 챕터 구간과 L2 요약 | 제목, 시작/종료 시간, 요약 |
| `segments` | 자막/STT/OCR이 병합된 원본 단위 | text, start_ts, end_ts, speaker, ocr_text, L1 요약 |
| `embeddings` | 검색용 벡터와 payload | segment_id, 모델명, 생성 시각, 청크 설정 |
| `lecture_notes` | 챕터 단위 Markdown 노트 | frontmatter, 상태, 모델 버전, 검증 결과 |
| `note_embeddings` | 정제 학습 노트 검색용 벡터 | note_section_id, 원본 segment ids, 모델명, 생성 시각 |
| `note_sections` | 노트 단락과 원본 매핑 | 제목, 순서, 본문, segment ids, 시작/종료 시간 |
| `note_glossary` | 근거가 있는 용어 정의 | 용어, 정의, 첫 등장 타임스탬프, 등장 위치 |
| `note_self_check` | 회상 질문 | 질문, 범위(section/chapter), 출처 |
| `correction_log` | STT/용어/맥락 교정 이력 | 원문, 수정안, confidence, reason, applied |
| `lecture_context` | 강의 도메인 맥락 | 도메인, 핵심 주제, 빈출어, 고유명사, register |
| `morphology_lemmas` | 한국어 형태소 분석 결과 | 표제어, 품사, 표면형, 등장 횟수, 받침 여부 |
| `validation_log` | 출력 검증 결과 | 규칙명, 상태, 자동 수정 여부, 실패 사유 |
| `flashcards` | Anki 후보 또는 내보낸 카드 | 유형, 앞면, 뒷면, 난이도, 출처 시간 |
| `quizzes` | 자동 퀴즈 | 문제, 보기, 정답, 해설, 출처 |
| `concepts` / `concept_links` / `concept_relations` | 후속 개념 그래프 | 개념, 관계, 출처 |

## Data To Preserve

- 원본 파일 경로 또는 객체 스토리지 키.
- 자막/STT 세그먼트와 타임스탬프.
- 원문 OCR 텍스트와 슬라이드 캡션.
- 노트/RAG 반영용 정제 OCR 텍스트.
- 임베딩 모델명, 생성 시각, 청크 설정.
- L1/L2/L3 요약, RAG 인용, 학습 노트, 카드, 퀴즈, 생성 모델 버전.
- 학습 노트 단계별 중간 산출물: `cleaned`, `structured`, `rewritten`, `augmented`, `validated`.
- 자동 교정 원문, 수정안, confidence, reasoning, applied 상태.
- 작업 상태, 오류 로그, 재시도 이력, 비용/토큰 사용량.

## Sensitivity

| 데이터 | 민감도 | 처리 원칙 |
|---|---|---|
| 강의 파일, 자막, STT 대본 | 높음 | 사용자 소유 자료로 취급, 자동 공유 금지 |
| OCR 텍스트와 화면 캡처 | 높음 | 코드/계정/개인정보가 포함될 수 있으므로 로그 제한 |
| 학습 노트, 카드, 퀴즈 | 중~높음 | 원본 저작권을 이어받는 파생 학습 자료로 취급 |
| 질문 내용과 검색 로그 | 중 | 개인 관심사와 학습 기록으로 취급 |
| API 키, 로컬 파일 경로 | 높음 | 평문 로그와 문서 저장 금지 |

## Retention And Deletion

- 사용자가 강의를 삭제하면 원본 파일 참조, 세그먼트, 임베딩, 요약, 노트, 카드, 퀴즈, 교정/검증 로그, 캐시를 함께 삭제합니다.
- LLM/OCR 호출 결과는 재현성과 비용 절감을 위해 캐시할 수 있지만, 사용자 삭제 요청 시 함께 제거합니다.
- 프롬프트/모델 버전이 바뀌면 단계별 캐시를 무효화하거나 stale 상태로 표시하되, 자동 재생성은 하지 않습니다.
- 재생성은 사용자가 수동 재생성 버튼 또는 명시적 명령을 실행할 때만 수행합니다.
- API 키와 인증 정보는 데이터베이스, 문서, 로그에 평문 저장하지 않습니다.

## Migration Rules

- 마이그레이션은 한 번에 하나의 의도만 담습니다.
- 새 컬럼은 nullable 또는 default 값으로 추가하고, 코드 배포 후 NOT NULL을 설정합니다.
- 이름 변경은 새 컬럼 추가 → 양쪽 쓰기 → 읽기 이전 → 옛 컬럼 제거의 단계로 진행합니다.
- 마이그레이션 파일은 시간순으로 누적되며 과거 파일은 수정하지 않습니다.
- 임베딩 차원, 모델명, prompt 버전처럼 재생성에 영향을 주는 필드는 명시적으로 버전 관리합니다.

## Irreversible Operations

| 작업 | 원칙 |
|---|---|
| 강의 삭제 | 관련 파생 데이터와 캐시까지 삭제 대상 목록을 먼저 표시 |
| 임베딩 재생성 | 기존 벡터 무효화 기준과 rollback 가능성을 기록 |
| 대량 UPDATE/DELETE | 대상 건수를 먼저 SELECT로 확인 |
| 스키마 마이그레이션 | 롤백 스크립트 또는 전략을 함께 준비 |
| 외부 시스템 호출 | 멱등성 확인 후 실행, 실패 시 재시도 영향 기록 |

## Verification After Change

- 영향받는 행 수를 사전 추정과 비교합니다.
- 대표 강의 1개에서 segment → chunk → embedding → summary → note 매핑이 유지되는지 확인합니다.
- 삭제 후 검색, 노트, 카드, 퀴즈, 캐시에 잔존 데이터가 없는지 확인합니다.
- 빈 결과, 누락 필드, 낮은 confidence 교정 후보처럼 비정상 흐름도 함께 확인합니다.
